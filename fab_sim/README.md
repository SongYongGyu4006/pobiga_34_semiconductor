# 반도체 공정 수율 시뮬레이터

파라미터를 조절하면 각 공정의 예측값과 최종 수율이 실시간으로 갱신된다.

---

## 실행

```bash
pip install -r requirements.txt

# 모델 6개를 backend/models/artifacts/ 에 넣은 뒤
cd backend
uvicorn app:app --port 8000
```

브라우저에서 `http://localhost:8000`

모델 총 용량이 약 2GB 이므로 첫 기동에 20~30초가 걸린다.
`--reload` 는 파일이 바뀔 때마다 모델을 다시 읽으므로 개발 중에도 끄는 편이 낫다.

---

## 모델 연결 구조

| # | 모델 | 입력 | 출력 |
|---|---|---|---|
| 1 | oxidation | 산화 파라미터 | `Ox_Thickness` |
| 2 | softbake | 산화 파라미터 + `Ox_Thickness` + 소프트베이크 파라미터 | `resist_uniformity` |
| 3 | lithography | 위 전부 + 리소 파라미터 | `CD` |
| 4 | etch_total | 위 전부 + 식각 파라미터(선택비 제외) | `Etch_Total_Drop` |
| 5 | etch_selectivity | 위 전부 + `Etch_Total_Drop` | `Selectivity` |
| 6 | final_target | 위 전부 + 이온 주입 파라미터 (`Selectivity` 제외) | `Target` |

상류 예측값은 **출력 컬럼 이름 그대로** 컨텍스트에 들어가므로,
하류 모델의 `feature_names_in_` 에 그 이름이 있으면 자동으로 연결된다.

수율(%) = `(1 - Target / 533) x 100`

---

## 식각 공정의 파생변수

프론트에서 사용자가 조절하는 값은 **박막 두께 F1 / F2 / F3** 이고,
모델이 쓰는 값은 구간 식각량이다. 파이프라인이 자동 계산한다.

| 파생값 | 계산식 |
|---|---|
| `Etch_Drop_10_20` | F1 − F2 |
| `Etch_Drop_20_30` | F2 − F3 |
| `Etch_Total_Drop` | 4번 모델의 예측값 |

파생값은 화면에 `AUTO` 표시와 함께 읽기 전용으로 나타나며,
F1~F3 슬라이더를 움직여야 변한다.

---

## 이온 주입 공정

출력 변수가 확정되지 않아 **프론트에서는 표시하지 않는다.**
다만 최종 수율 모델의 입력에는 필요하므로, `schema.json` 의
`implant` 스테이지가 `hidden: true` 로 남아 기본값(중앙값)을 계속 전달한다.

다시 노출하려면 `build_schema.py` 의 `STAGES` 에서 `"hidden": True` 를 지우고
`models` 에 항목을 추가한 뒤 스키마를 다시 생성하면 된다.

## 챔버 최적 경로 조합

실제 라인은 챔버 3개를 **동시에 운용**하므로, 경로 하나가 아니라
**서로 챔버가 겹치지 않는 경로 3개의 조합**을 찾는다.

| 항목 | 내용 |
|---|---|
| 제약 | 각 공정에서 세 경로의 챔버가 모두 달라야 함 (열 방향 {1,2,3} 순열) |
| 목적 | 세 경로 예측 수율의 **평균 최대화** |
| 탐색량 | 조절한 공정부터 재탐색. 앞 공정 배정은 그대로 유지 |
| 소요 | 0.2초 (필요한 경로만 배치로 계산 후 조합은 조회만) |

### 재탐색 범위

| 조절한 공정 | 고정 | 재탐색 | 조합 수 |
|---|---|---|---|
| 산화 | — | 4개 공정 | 216 |
| Soft Bake | 산화 | 3개 공정 | 216 |
| Lithography | 산화 · 베이크 | 2개 공정 | 36 |
| 식각 · 이온 | 산화 · 베이크 · 리소 | 1개 공정 | 6 |

앞 공정의 챔버 배정은 **직전에 추천된 조합을 그대로 물려받는다.**
프론트가 현재 세 라인의 경로를 함께 보내고, 백엔드가 그 앞부분을 잘라 고정한다.
화면에서는 고정 구간이 회색 밴드와 점선 노드로 구분된다.

예시

```
라인 1 : 1-2-1-2   82.78%
라인 2 : 2-1-3-1   83.98%
라인 3 : 3-3-2-3   83.20%
        ↑ ↑ ↑ ↑    평균 83.32%
        각 열이 {1,2,3} 순열
```

라인 구분은 **산화 챔버 번호**로 고정한다. 라인 라벨을 바꿔도 같은 조합이므로
중복 탐색을 피하기 위해서다.

### API

```
POST /api/routeset
{ "params": {...}, "top_n": 3 }
```

### 프론트 시각화

`4개 공정 × 챔버 3개 = 12개 노드` 위에 세 경로를 색이 다른 선으로 잇는다.
라인 목록을 클릭하면 그 라인의 챔버 조합이 슬라이더에 적용된다.

## 단일 경로 추천 (기존)

파라미터를 조절하면, **그 파라미터가 속한 공정부터 마지막 공정까지**의
챔버 조합을 전수 탐색해 수율이 가장 높은 경로를 추천한다.
앞선 공정의 챔버는 현재 선택값 그대로 고정한다.

| 조절한 공정 | 탐색 대상 | 조합 수 |
|---|---|---|
| 산화 | 산화 → 식각 (4개) | 3⁴ = 81 |
| Soft Bake | Soft Bake → 식각 (3개) | 27 |
| Lithography | Litho → 식각 (2개) | 9 |
| 식각 | 식각 (1개) | 3 |
| 이온 주입 | 식각 (연동) | 3 |

81개 조합도 **0.2초 이내**에 끝난다. 한 건씩 돌리지 않고
모델마다 전체 조합을 한 번에 예측(`Pipeline.run_frame`)하기 때문이다.

### 이온 챔버 연동

원본 데이터에서 `Ion_Chamber` 와 `Etching_Chamber` 의 값이 **100% 일치**한다.
두 챔버를 독립적으로 조합하면 학습 데이터에 없는 경로를 추천하게 되므로,
`build_schema.py` 의 `MIRROR` 설정으로 묶었다.

```python
MIRROR = {"Ion_Chamber": "Etching_Chamber"}
```

| 반영 위치 | 동작 |
|---|---|
| `Pipeline.merge` | 항상 `Ion_Chamber = Etching_Chamber` 로 덮어씀 |
| 챔버 경로 탐색 | 이온 챔버를 차원에서 제외 (243 → 81) |
| 프론트 | `LINK` 배지가 붙은 읽기 전용 버튼. 식각 챔버를 따라 자동 변경 |

다른 컬럼 쌍에서 같은 문제가 발견되면 `MIRROR` 에 추가하고
스키마를 다시 생성하면 된다. 생성 시 일치율이 로그로 출력된다.

`추천 경로 적용` 버튼을 누르면 챔버 버튼이 실제로 바뀌고 예측이 다시 돈다.

### API

```
POST /api/recommend
{ "params": {...}, "from_stage": "etch", "top_n": 5 }
```

`from_stage` 를 생략하면 첫 공정부터 전체를 탐색한다.

## Process Window

권장 조업 구간을 **슬라이더 범위 자체**로 적용한다.
`build_schema.py` 의 `PROCESS_WINDOW` 에서 정의한다.

### S5b 윈도우 (현행)

| 변수 | 하한 | 상한 | 단독 coverage |
|---|---|---|---|
| `temp_softbake` | 91.225 | 93.561 | 60.0% |
| `spin3_rpm` | 4976.007 | 5101.350 | 60.0% |
| `temp_HMDS_bake` | 199.252 | 204.353 | 55.0% |
| `Furnace_Temp` | 898 | 924 | 58.0% |
| `Ion_Energy` | 31982.453 | 32302.259 | 35.0% |

이 목록에 없는 파라미터는 **데이터의 min / max 를 그대로** 슬라이더 범위로 쓴다.
`build_schema.py` 의 `PROCESS_WINDOW` 하나만 고치면 아래가 모두 따라온다.

| 연쇄 반영 | 내용 |
|---|---|
| 슬라이더 범위 | 창이 있으면 창, 없으면 데이터 min/max |
| 기본값 | 창 안 실측 중앙값 (창이 없으면 전체 중앙값) |
| 최대·최저 수율 탐색 | 슬라이더 범위 안에서만 탐색하므로 창을 벗어나지 않음 |
| 모니터링 빨간 표시 | 창이 걸린 변수만, 해당 공정에 진입했을 때 |
| `PW` 배지 | 창이 걸린 파라미터에 표시 |

| 변수 | 기본값 | 창 안 데이터 비율 |
|---|---|---|
| `temp_HMDS_bake` | 201.657 | 55.0% |
| `spin3_rpm` | 5033.570 | 60.0% |
| `temp_softbake` | 92.325 | 60.0% |
| `Ion_Energy` | 32222.259 | 35.0% |
| `Furnace_Temp` | 910.000 | 58.0% |

- 기본값은 **창 안에서 실제 관측된 값들의 중앙값**이다.
  전체 중앙값을 경계로 자르면 슬라이더가 끝에 붙어버리므로 이렇게 잡는다.
- 창 안 데이터가 없으면 창의 중점을 쓴다.
- 창이 데이터 범위를 벗어나면 원본 범위를 유지한다.
- 원본 범위는 `data_min` / `data_max`, 창 정보는 `window` 에 남는다.

## 챔버 최적 경로 조합 (실시간 탐색)

경로 조합은 **현재 파라미터로 매번 새로 계산**한다.
고정된 확정 경로는 사용하지 않는다.

| 항목 | 내용 |
|---|---|
| 계산 시점 | 파라미터를 바꿀 때마다 |
| 목적 | 라인 예측 수율의 **평균 최대** |
| 제약 | 각 공정에서 라인끼리 챔버가 겹치지 않음 |
| 배지 | `실시간 탐색` |

고정값을 다시 쓰려면 `build_schema.py` 의 `FIXED_ROUTE_SET` 을 채우면 된다.
값이 있으면 자동으로 확정 모드로 전환된다.

## 사용 가능 챔버 · 경로 탐색 (폴백)

각 공정의 챔버 버튼은 **사용 가능 여부를 고르는 다중 선택**이다.
최소 1개는 남으며, 끄면 해당 챔버는 경로 탐색에서 제외된다.

| 규칙 | 내용 |
|---|---|
| 라인 수 | 공정별 사용 가능 챔버 개수의 **최솟값** |
| 제약 | 각 공정에서 라인끼리 챔버가 겹치지 않음 |
| 목적 | 라인 예측 수율의 **평균 최대화** |
| 단건 예측 | 선택한 **예측 기준 라인**의 챔버 기준 (기본: 라인 1) |

예시

| 설정 | 라인 수 |
|---|---|
| 전부 사용 | 3 |
| 리소 2개만 | 2 |
| 리소 2개 · 식각 2개 | 2 |
| 리소 1개만 | 1 |

패널 상단에 라인 수와 **병목 공정**(가용 챔버가 가장 적은 공정)이 표시된다.
경로도에서 사용 불가 챔버는 점선 회색 노드로 구분된다.

### 챔버 컨트롤은 두 줄

| 줄 | 역할 | 방식 |
|---|---|---|
| **챔버 선택** | 좌측 단건 예측이 사용할 챔버 | 단일 선택 |
| **사용 가능** | 경로 조합 탐색 대상 | 다중 선택 |

- 사용 가능에서 끈 챔버는 선택 줄에서 점선·흐림으로 표시되고, 고를 수 없다.
- 선택했던 챔버를 끄면 첫 번째 가용 챔버로 자동 이동한다.
- 라인 목록을 누르면 그 라인의 챔버가 **선택 줄에만** 반영된다.
  좌측 수율 패널에 `라인 2 (2-3-3-1) 기준`처럼 표시되고,
  직접 고른 경우 `직접 선택한 챔버 기준`으로 바뀐다.

## 생산 운영 모니터링 (`/monitor`)

시뮬레이터 상단의 `생산 모니터링` 버튼을 누르면 새 탭에서 열린다.
실제 Lot 이 라인에 투입되는 상황을 틱 단위로 진행하며,
공정 진입 시점마다 챔버를 다시 추천한다.

### 동작

| 단계 | 내용 |
|---|---|
| 투입 | 원본 CSV 에서 **날짜 하나**를 골라 그날 생산분을 대기열로 생성 |
| 조건 | **과거 챔버는 버리고 공정조건만** 가져온다 |
| 진행 | 각 챔버가 정해진 틱 수만큼 진행률을 올린다 (공정별 12~22틱) |
| 완료 | 진행률 100% 에서 그 공정 Output 을 예측하고 다음 공정 대기열로 이동 |
| 배정 | 동시 진입 Wafer 들을 함께 보고 **챔버가 겹치지 않게** 배정 |
| 목적 | 개별 최선이 아니라 **동시 투입 Wafer 전체의 예상 수율 합** 최대 |
| 최종 | 마지막 공정 후 Target · 예상 수율 계산 → History 누적 |

챔버 후보 평가는 그 시점까지 누적된 조건과 앞 공정 예측 Output 을 반영한다.
뒤쪽 미정 공정은 기준 챔버로 고정해 후보 간 비교만 공정하게 만든다.

### 화면

| 영역 | 내용 |
|---|---|
| 공정 라인 | 공정 **5개** × 챔버 3개. `RUNNING` / `AVAILABLE`, 진행률 바, 대기 칩 |
| LOT 현황 | Total · Waiting · Running · Completed · 진행률 · 평균 예상 수율 |
| Wafer 상세 | 공정 이력(챔버·Output)과 **챔버 추천 근거**(후보별 예상 수율) |
| History | 완료 Wafer 의 챔버 경로와 예상 수율 누적 |

라인의 챔버 칸이나 History 항목을 클릭하면 상세가 열린다.

### 조작

| 버튼 | 동작 |
|---|---|
| 날짜 | 투입할 날짜 선택 (181일) |
| 투입량 | 15 / 30 / 54장 또는 전량 |
| 투입 | 선택한 날짜·매수로 새로 투입 |
| 시작 / 일시정지 | 0.7초 간격 자동 진행 |
| 한 틱 | 한 틱만 진행 |

### API

|---|---|---|

| POST | `/api/monitor/tick` | `{n}` n틱 진행 |

| GET | `/api/monitor/wafer/{id}` | Wafer 상세 |

### 데이터 경로

### 이온 주입 공정

`Ion_Chamber` 는 `Etching_Chamber` 와 100% 일치하므로 **추천하지 않고 연동**한다.
식각에서 쓴 챔버 번호를 그대로 따라가며, 같은 번호가 아직 사용 중이면 대기한다.
공정 헤더에 `식각 공정 연동` 배지가 붙고, 추천 근거에는 후보 점수 대신 연동 표시가 나온다.

### 경로를 어떻게 보여주는가

라인 화면은 **"지금 어느 챔버가 점유 중인가"** 를 보여주고,
경로는 **"한 Wafer 가 시간에 따라 거쳐온 순서"** 다. 축이 다르다.
둘을 같은 그림에 겹치면 이미 떠난 챔버에 다른 Wafer 가 들어와 있어 선이 어긋난다.

그래서 두 층으로 나눴다.

| 층 | 표현 | 목적 |
|---|---|---|
| 라인 화면 | 챔버 칸의 **왼쪽 색 띠 + 진행률 바 색** = 점유 중인 Wafer 색 | 지금 누가 어디 있는지 |
| 경로 트레이스 | 우측 패널의 **공정 × 챔버 격자 미니맵** | 선택한 Wafer 한 장의 경로 |

- Wafer 색은 번호로 고정되어 라인 · History · 트레이스에서 동일하다.
- 트레이스는 지나온 구간을 실선, 진행 중인 공정을 점선으로 잇는다.
  아직 정해지지 않은 뒤쪽 공정은 그리지 않는다 (진입 시점에 다시 추천되므로).
- `완료 경로 겹쳐보기` 를 켜면 최근 완료 5건이 옅은 선으로 함께 깔린다.
  선을 늘리면 겹쳐 보이므로 5건으로 제한했다.

### 속도 조절

상단 `속도` 에서 0.5x / 1x / 2x / 5x 를 고른다. 1x 는 0.8초에 한 틱이다.
공정 시간은 `monitor.py` 의 `STAGE_TICKS` 에서 조정한다.


### 챔버 사용 중지 (정비 모드)

각 챔버 칸 우측 상단의 `◼` 버튼으로 챔버를 닫을 수 있다.

| 상태 | 의미 |
|---|---|
| `AVAILABLE` | 비어 있고 배정 가능 |
| `RUNNING` | 처리 중 |
| `CLOSING` | 닫도록 지정됐지만 현재 Wafer 를 끝내는 중. 이후 새 배정 없음 |
| `DISABLED` | 닫혀 있고 비어 있음 (빗금 표시) |

- 진행 중인 Wafer 를 강제로 빼내지 않고 **마치고 나서 닫는다.**
- 식각 챔버를 닫으면 **이온 챔버도 같은 번호가 함께 닫힌다** (연동 관계).
  이온 공정 칸에는 자물쇠 표시만 있고 직접 조작할 수 없다.
- 한 공정의 챔버를 모두 닫으면 진행이 멈추므로 **최소 1개는 열려 있어야 한다.**
  마지막 하나를 닫으려 하면 경고가 뜨고 취소된다.
- 설정은 `투입` 을 다시 눌러도 유지된다.

```
POST /api/monitor/chamber
{ "stage": "etch", "chamber": "1", "enabled": false }
```


### 동시 요청 처리

FastAPI 는 동기 엔드포인트를 스레드풀에서 처리하므로, 자동 진행 중에
챔버를 조작하면 두 요청이 동시에 엔진 상태를 바꿀 수 있다.
그 틈에 같은 Wafer 가 두 슬롯에 배정되면 한 공정을 두 번 끝내
경로에 `None` 이 섞여 들어간다.

세 겹으로 막았다.

| 층 | 조치 |
|---|---|
| 엔진 | `threading.RLock` 으로 `start` · `tick` · `set_chamber` · `state` 직렬화 |
| 배정 | 대기열에서 `waiting` 이 아닌 Wafer 를 걸러내고 중복 등록을 막음 |
| 완료 | 이미 처리된 Wafer 의 슬롯은 기록 없이 비우기만 함 |
| 프론트 | 앞 요청이 끝나기 전에는 다음 틱·토글 요청을 보내지 않음 |

틱 3스레드 + 토글 3스레드로 25초간 동시 호출해도 경로 길이가 모두 5로
유지되고 `None` 이 발생하지 않는 것을 확인했다.


### 추천 경로 vs 실제 기록 경로

Wafer 가 완료되면 **같은 공정조건에 원본 CSV 의 챔버를 그대로 넣어** 한 번 더 평가한다.
두 값 모두 같은 모델의 예측이므로 차이가 곧 **경로 추천의 순수 효과**다.

| 비교 | 타당성 |
|---|---|
| 실측 수율 vs 추천 경로 예측 | ✗ 모델 오차가 섞여 개선폭을 주장할 수 없다 |
| **실제 경로 예측 vs 추천 경로 예측** | ✓ 조건은 동일, 챔버만 다르므로 순수 비교 |

표시 위치

| 영역 | 내용 |
|---|---|
| LOT 현황 | 추천 평균 · 실제 경로 평균 · **평균 개선폭** · 개선/악화 건수 |
| History | 각 행에 추천 경로와 `실제 …` 경로, 수율과 개선폭(`+1.36%p`) |
| Wafer 상세 | 추천 · 실제 · 개선폭 3행 비교표 |

LOT 15 (27장) 실행 결과: 추천 82.11% vs 실제 81.19%, **평균 +0.93%p, 개선 18건 · 악화 7건**.

개선폭이 음수인 Wafer 도 있다. 경로 추천은 그 시점의 예상 수율이 가장 높은 챔버를
고르지만, 뒤쪽 공정 챔버는 아직 정해지지 않아 기준값으로 두고 비교하기 때문이다.
전체 평균으로는 이득이지만 개별로는 뒤집힐 수 있다는 점을 함께 보여준다.


### 앞으로 갈 예상 경로

Wafer 를 선택하면 **아직 지나지 않은 공정의 예상 챔버**까지 함께 보여준다.

| 구간 | 트레이스 표현 |
|---|---|
| 지나온 공정 | 실선 + 채운 노드 |
| 진행 중인 공정 | 굵은 점선 + 테두리 노드 |
| **앞으로 갈 공정** | **얇은 점선 + 빈 노드** |

상세 패널에는 공정별 후보 점수와 선택 챔버, 그리고 **예상 최종 수율**이 나온다.

### 동승 그룹 (겹침 방지)

같은 타이밍에 들어가는 Wafer 들은 실제로 챔버가 겹치지 않게 배정된다.
Wafer 하나만 놓고 최선을 고르면 여러 Wafer 의 예상 경로가 똑같이 겹쳐 보이므로,
**다음 공정이 같은 Wafer 들을 묶어 겹치지 않는 조합 중 합이 최대인 배정**을 고른다.

| 항목 | 내용 |
|---|---|
| 그룹 구성 | 다음 공정이 같은 Wafer 를 진행률 순으로 정렬 후 챔버 수만큼 묶음 |
| 배정 | 그룹 전체의 예상 수율 합이 최대가 되는 겹치지 않는 조합 |
| 이후 공정 | 같은 그룹이 함께 이동한다고 보고 계속 배정 |

상세 패널에 `함께 투입되는 Wafer` 목록이 나오고, 각자의 예상 경로가 표시된다.
예: `W10 3→2→3→3` · `W11 2→1→1→1` · `W12 1→3→2→2` — 각 열에 중복이 없다.

### 앞으로 갈 예상 경로

Wafer 를 선택하면 남은 공정의 예상 챔버를 즉시 계산해 보여준다.
같은 시점에 들어가는 Wafer 들은 챔버가 겹치지 않게 함께 배정한다.

챔버 점유 시점까지 재현하는 정밀 예측은 **제거했다.**
계산에 2~3초가 걸리는 데 비해 결과 차이가 0.4%p 수준이었고,
어차피 실제 진입 시점에 다시 계산되므로 미리 정확히 아는 의미가 작다.

### 색의 의미

화면에서 색은 한 가지 뜻만 갖도록 정리했다.

| 요소 | 색 |
|---|---|
| 챔버 진행률 바 | **항상 같은 민트** (Wafer 색을 쓰면 어두운 색이 빈 트랙과 헷갈린다) |
| 빈 트랙 · AVAILABLE · DISABLED | 회색 |
| 선택한 Wafer | 라인·대기열·History 에서 **테두리 강조** (색이 아니라 굵기·명도) |
| Wafer 개별 색 | **여러 Wafer 가 한 화면에 겹칠 때만** 사용 — 완료 경로 겹쳐보기, 동승 그룹 목록 |
| 윈도우 이탈 | 빨강 (해당 공정에 진입했을 때만) |

라인에서는 한 Wafer 가 한 곳에만 있으므로 Wafer 별 색을 쓰지 않는다.
색이 다르면 의미가 있어 보이지만 실제로는 번호로 돌려 찍은 태그일 뿐이라 오해를 준다.
대신 Wafer 를 클릭하면 라인·대기열·History 어디에 있든 테두리로 강조된다.
LOT 진행률 막대는 초록이 완료 비율, 회색이 남은 비율이며 막대 아래에 안내 문구가 있다.

## Process Window (현재 미사용)

공정 윈도우는 적용하지 않는다. 모든 파라미터의 슬라이더 범위는
**데이터의 최소~최대**를 그대로 쓰고, 기본값은 중앙값이다.

| 항목 | 상태 |
|---|---|
| 슬라이더 범위 | 데이터 min / max (26개 수치형 전부) |
| 기본값 | 데이터 중앙값 |
| 최대·최저 수율 탐색 | 데이터 범위 안에서 탐색 |
| `PW` 배지 | 표시 안 함 |
| 모니터링 빨간 표시 | 없음 |
| Wafer 상세 이탈 목록 | 없음 |

### 다시 도입하려면

`build_schema.py` 의 `PROCESS_WINDOW` 만 채우면 위 항목이 **모두 자동으로 살아난다.**

```python
PROCESS_WINDOW = {
    "temp_softbake": {"min": 91.225, "max": 93.561},
    ...
}
```

스키마에 `window` 키가 생기면 프론트 배지, 모니터링 판정, 기본값 재계산이
따라서 동작하도록 코드가 조건부로 짜여 있다.

## 투입 단위 : 날짜

Lot 단위가 아니라 **날짜 단위**로 투입한다.

| 근거 | 내용 |
|---|---|
| 실제 라인 재현 | 하루에 Lot 이 1~2개 흐른다 (108일은 2개, 73일은 1개) |
| 챔버 경쟁 | Lot 단위로는 **서로 다른 Lot 이 챔버를 두고 경쟁하는 상황**이 빠진다 |
| 선택 임의성 제거 | 같은 (Lot, Wafer_Num) 이 9개 날짜에 중복 기록되어 있어, Lot 단위는 그중 하나를 임의로 골라야 했다 |

### 투입량 상한

그날 전량은 54장 또는 108장이라 완주에 오래 걸린다 (108장 ≈ 800틱).
상단에서 **15 / 30 / 54장 / 전량**을 고른다. 기본값은 30장이다.

Lot 이 둘인 날은 `Wafer_Num` 순으로 정렬해 뽑으므로 **두 Lot 이 절반씩 섞여** 들어간다.
Lot 순으로 자르면 앞 Lot 만 들어가 경쟁 상황이 사라지기 때문이다.

| 설정 | 결과 |
|---|---|
| 30장 | Lot 1 : 15장 · Lot 21 : 15장 |
| 전량 | Lot 1 : 54장 · Lot 21 : 54장 |

### Lot 표시

같은 날 두 Lot 이 섞이면 `Wafer_Num` 이 겹치므로,
챔버 칸 · 대기 칩 · History · 상세에 **Lot 배지**(`L1`, `L21`)를 함께 표시한다.

## 공정별 최적 경로 조합 (메인 기능)

라인의 **공정 이름을 클릭**하면 가운데 패널에 그 공정의 챔버 3개에 있는
Wafer 들이 앞으로 갈 경로가 **카드 3장**으로 나온다.

### 화면 구성 (3열)

| 열 | 내용 |
|---|---|
| 좌 | 공정 라인 (공정 5 × 챔버 3) + 완료 History |
| **중** | **챔버 최적 경로 조합** — 조합 평균 + 카드 3장 |
| 우 | 생산 현황 · Wafer 상세 |

### 카드 구성

```
Ch1  W07 L21                    81.74%
 [리소 ①] → [식각 ③] → [이온 ③]
 다음 공정 후보  Ch1 81.208  Ch2 81.361  [Ch3 81.744]
```

| 요소 | 의미 |
|---|---|
| 좌측 색 띠 | 현재 챔버 (Ch1 초록 · Ch2 주황 · Ch3 파랑) |
| 첫 스텝 (색 채움) | 지금 있는 공정과 챔버 |
| 이후 스텝 | 앞으로 갈 공정과 챔버 |
| 다음 공정 후보 | 챔버별 예상 수율, 선택된 것만 색으로 강조 |
| 상단 조합 평균 | 세 Wafer 예상 수율의 평균 |

카드를 클릭하면 우측에 그 Wafer 의 상세가 열린다.

### 선을 쓰지 않은 이유

라인 위에 선을 겹쳐 그리면 교차가 많아 읽기 어렵고,
좌측 라인이 이미 흐름을 담당하므로 역할이 겹친다.
카드는 **챔버별로 분리**되어 좁은 폭에서도 안정적이고,
후보 점수를 함께 넣을 공간이 나온다.

### 계산

그 공정의 Wafer 들을 한 묶음으로 놓고, 남은 공정마다 서로 챔버가
겹치지 않는 조합 중 **예상 수율 합이 최대**인 배정을 고른다.
개별 최선을 따로 고르면 셋 다 같은 챔버를 답해 실제와 어긋난다.

```
GET /api/monitor/stage/{stage_id}/routes
```

소요 0.7~1.1초 (앞 공정일수록 남은 공정이 많아 오래 걸린다).

**자동 갱신은 하지 않는다.** 경로 계산은 틱(67ms)보다 11~16배 비싸서,
반복하면 라인 진행이 밀린다. 결과 상단에 `tick N 기준` 이 표시되고,
`다시 계산` 을 눌러야 최신 상태로 갱신된다.

| 상태 | 틱 속도 |
|---|---|
| 경로 창 없음 | 초당 4.6 tick |
| 경로 창 열림 | 초당 4.5 tick (97% 유지) |
